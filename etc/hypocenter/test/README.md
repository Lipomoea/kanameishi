# Hypocenter checks

Both profiles rank competing travel-time matches by the mean absolute P/S residual over the new pick itself and its current legal inference-neighbor triggers, once per station at equal weight. Candidates must first pass the existing own-pick arrival gate. Keep candidates within 500 ms (inclusive) of the minimum mean; among survivors keep those within 500 ms (inclusive) of the minimum own-pick residual; choose the nearest epicenter, then the lowest cluster ID for an exact distance tie. Zero/one-candidate paths skip neighborhood scoring. `cluster_matching.mjs`, run by the PAlert suite, checks both profiles, threshold boundaries, order independence, self inclusion, weak neighbors, and Worker forwarding/coalescing.

Components send `triggerStations` from all currently legal station triggers, including weak/unactivated stations that submit no pick. This evidence does not itself activate stations, create picks, or wake clusters. Each processed frame replaces the entire snapshot before association; pending-message merging retains only the latest frame's trigger evidence while still accumulating submitted picks. Direct replay callers should pass this snapshot as the fifth `Finder.update` argument. Legacy callers fall back to that update's active-station snapshots. Dormancy lasts 30 seconds and both existing merge entry points retain their behavior.

NIED and PAlert retain finished clusters in the existing Finder with `dormantSince` set to the current data-frame timestamp. This includes subthreshold clusters without a hypocenter. Dormant clusters retain picks, indexes, the last solution and previous phase fits, and continue normal association and merging while skipping inference; public/display results omit them. Pick metrics, trigger snapshots and inactive-candidate membership still update, with dirty state retained until waking. A newly accepted pick ID from a currently active station wakes a matching cluster, even if its onset predates dormancy, and it is refitted with current inputs in that frame. Repeated observations, updated metrics and station reactivation alone do not wake it or extend its deadline. Merging with an active cluster wakes it; merging two dormant clusters retains the earliest dormant start and a prior solved member's model for travel-time association, preferring the usual merge base among solved members. The merged picks are fitted only after waking. NIED retains its global pick-station exclusions until the last pick for a station is removed; PAlert retains its cluster-start/non-quiet-boundary eligibility rule and excludes only the current cluster's stations. Expiry occurs strictly after 30,000 ms, before new-pick association, and clears the cluster's pick/index state. A later sleep starts a fresh interval.

Both components forward quiet frames and explicit `frameStamp` values. Workers retain Finder while any clusters remain, release it when both active stations and retained clusters are empty, and continue honoring explicit timeline resets/reinitialization. Direct `Finder.update` callers should supply the fourth argument, especially for empty frames; the compatibility fallback reads snapshot `updateStamp` values, never wall-clock time. `cluster_dormancy.mjs`, run by the PAlert suite, checks both production profiles and Workers, including the exact 30-second boundary, data-time jumps, backdated and repeated picks, suspended inference and same-frame refitting on wake, frozen-model association through both merge paths, inactive-candidate cache invalidation, queued inactive observations, complete cleanup and reset. The original NIED equivalence test compares active solver state separately from this intentional retention difference.

`nied_trigger.mjs` checks the production NIED station's trigger history. Only an isolated cumulative rise of one level has a four-sample plateau limit; an ongoing larger rise such as `1 -> 8 -> 9` retains eight samples. The decision uses the rise before each plateau, so a later strong jump cannot revive an expired weak rise. Cases cover both timeout boundaries, connected and expired preceding rises, short/deep/shallow valleys, missing data, and unchanged activation state. Counts follow the existing one-sample-per-second history convention; the missing-data timeout and activation timer are unchanged.

The weak-prefix pass reads the same valley-smoothed history as the original backward search. Filled valley and missing-data samples count toward plateau duration. If trimming places the onset on a filled sample, its time remains uncertain and `triggerStamp` stays zero even when `ascend` is positive; there is no fallback to an earlier real sample. Regression cases cover invalid onsets on one- or two-sample filled valleys and missing gaps, a later real plateau sample providing a valid onset, the four-sample boundary across a filled valley, and an already-established strong rise continuing across a valley.

`EewNetworkRelations.js` centralizes the CWA/P-Alert/TREM, JMA/NIED and KMA relationships. The association checks cover view bounds, hidden detection grids, independent network period statistics and inferred-hypocenter matching. Grid visibility remains separate from participation in view bounds; the always-on inference setting bypasses matching suppression but retains the quality threshold.

`compareFloat` rounds both operands to ten decimal places by default. P-Alert PGA/activity thresholds, inferred-hypocenter coordinate matching and cluster merging use it at their explicit comparison boundaries. Grid offsets use `exactRound` with ten decimal places before `Math.round`; distance calculations clamp the haversine intermediate value to `[0, 1]`. The numeric checks cover both sides of each boundary, negative grid coordinates, scientific notation, invalid values and antipodal/near-antipodal distances. Weighted origin times and residual filtering retain their existing calculations.

The P-Alert suite also exercises station-list polling in both P-Alert and TREM. Each starts immediately, retries twenty seconds (P-Alert) or ten seconds (TREM) after a request completes while no usable station metadata is cached, and refreshes every ten minutes once a valid list is available. Tests cover malformed and partial responses, preservation of cached metadata after refresh failures, and unmount during a pending request or scheduled delay.

NIED, P-Alert and TREM share `StationFrameQueue`, with an independent instance for each source. The `displaySeisNet.httpDataPriority` setting defaults to `realtime`, which commits successful responses immediately. In `complete` mode, one distinct later frame may wait behind unfinished requests; two distinct ready timestamps displace a blocking unfinished frame. Duplicate timestamps do not consume additional waiting allowance. NIED groups its 500ms attempts by the requested second, so any successful attempt satisfies that frame and failures wait only while another attempt is pending. Timestamp-specific replay requests also group by their requested second. P-Alert frames become ready after optional PGV retrieval; a PGV failure retains valid PGA. Failed, malformed and discarded requests cannot block indefinitely or reappear on late completion. Timeline resets discard pending work and allow an earlier timestamp; mode/source changes discard pending work while preserving committed time and station history. Tests exercise all three actual request callbacks with deferred responses, all three-frame return permutations, duplicate attempts, the one-frame limit, failure/timeout release, PGA/PGV readiness and lifecycle isolation. The queue preserves available frames; it cannot recover server-side gaps or missing station measurements.

The suite also checks NIED and P-Alert inference lifecycle handling. NIED validates both the Worker instance and request ID, ignores errors from replaced Workers, and clears displayed inference on a current Worker error. Initialization and reset discard pending work and the existing finder; reset retains adjacency. Virtual task-queue tests cover stale callbacks across generations. Both renderers keep inferred waves, epicenters and labels in a Leaflet layer group, remove the old group and label listeners when the map changes, and destroy them on unmount. Renderer checks cover result replacement, map replacement, disabled display, label modes, pane ownership and cleanup while retaining the source-specific time zone and label styling.

`compare_nied_profile.mjs` compares the current NIED finder with the original implementation at commit `2a420f4c5fe435688a6862147e0967e9393623fc` without modifying the baseline. Parameter checks allow only the intentional S/P cap changes among the original parameters, retaining the original thresholds and filter eligibility. Separate production-policy checks cover fractional ratios, saturation, zero caps and pure S/S-heavy/pure P scoring through all PREV stages. Equivalence comparisons restore the original caps only on isolated comparison finders; sequential comparisons also supply the original density-weight table and disable the breadth station bonus. They check sequential results, internal state, PREV behavior and profile isolation. Excess inactive evidence is checked separately as an intentional difference: the original rejects the candidate, while the current finder uses the uncapped ratio and returns a finite score. The current breadth defaults and their integration with actual search/refitting are exercised separately by `palert_inference.mjs`.

NIED and P-Alert compute an inactive-penalty breadth station bonus once before each search, using the unweighted mean great-circle distance of every unordered pair of distinct station IDs in the full cluster. Repeated picks from one station count once; distinct stations at identical coordinates still count separately. The weight uses `actualStationCount + breadthKm / 10`: each 10 km of mean pair distance adds one equivalent station, including fractional stations. The bonus has no separate cap; weight reaches zero at 50 equivalent stations, so a breadth of 100 km lets 40 actual stations reach zero weight. All candidate locations, phase scenarios and duplicate-pick refits share that fixed weight. The inactive-count denominator and minimum inference count still use actual distinct stations; equivalent stations affect only the penalty weight. The inactive ratio is the full penalized inactive count divided by the actual cluster station count, without a cap; excess inactive evidence raises the finite penalty instead of invalidating a candidate. Tests cover ratios below, at and above 1, finite shallow/deep candidate scores, the 10 km conversion, fractional bonuses, early zero weight, pair averaging, duplicate picks, collocated stations, missing coordinates and sharing across the actual search/refit lifecycle.

Both station components retain their already computed full roster distances as `Float64Array` rows with station-ID indexes. NIED builds separate time-tolerance rows instead of overwriting distances in km; P-Alert retains every pair, including stations outside its sparse adjacency lists. The table is sent once per Worker initialization, reused across finder resets, and replaced when station metadata initializes again. Breadth uses table lookups and additions for fewer than 50 stations, with at most 1,176 unordered pairs; it skips the calculation at 50 or more actual stations. Standalone callers without a table entry retain the coordinate-based fallback. Tests verify lookup without coordinate access, numeric/string IDs, shuffled indexes, zero distances, the component-to-Worker initialization message, distance/tolerance separation and table reuse/replacement.

NIED and P-Alert density weights both use `1 / sqrt(max(N, 1))`, where N counts initialized station neighbors at distances up to and including 30 km, including the station itself. Current data validity and activation do not affect this count, and distant neighbors added for directional connectivity are excluded. Each Worker computes the density table when it receives station initialization, reuses it across frame updates and finder resets, and replaces it on a new initialization. Direct finder construction without a supplied table computes the same policy once. The P-Alert suite verifies both source classes, the exact radius boundary, remote-link independence and Worker table reuse/reinitialization.

P-Alert inference retains all neighbors within 30 km, then fills each north/east/south/west direction to at least three neighbors by increasing distance, stopping at the inclusive 100 km boundary. The center station is retained but does not count toward any direction. A direction remains below three if too few stations exist within range; local directions already containing three or more receive no distant supplements. P-Alert activation neighborhoods retain every station within 30 km, including self. If fewer than four stations are present, the nearest stations beyond 30 km and up to the inclusive 40 km boundary fill the neighborhood to at most four; insufficient coverage stays below four. Each center selects independently, so supplemental edges need not be reciprocal. Trigger tolerances cover every selected activation neighbor. NIED activation neighborhoods and both sources' density weights retain the original 30 km radius. NIED uses the same supplementation rule with a minimum of two neighbors per direction and an inclusive 300 km limit, retaining its existing activation neighborhood. Tests cover nearest-first selection, preservation of all local neighbors, sparse/missing directions, the exact distance limits and density independence for both sources.

`palert_inference.mjs` covers trigger/missing-data boundaries, including the direct two-times PGA boundary, preferred one-frame backdating with a seven-point 1.5-times background, pick intervals sharing a boundary sample, complete preceding sample validation, cumulative top-two PGA renewal, closure after eight unchanged time points independently of activity, final-frame peak delivery, frozen completed picks, prevention of stale-trigger recovery, high-background onset validation, history-window independence, per-timestamp peak statistics, level-only activity, weighting, inactive penalties, cumulative message merging, Worker reuse/cancellation and settings access. Activity uses the maximum level in the latest twelve seconds: below 6 gives 0, levels 6/7/8/9 give 0.2/0.5/1/1.5, and level 10 or higher gives 2. The station's `activitySeconds` parameter controls this detection window independently of the pick lifecycle. Detection requires an activity sum of at least `max(neighborCount * activityRatio, minActivity)`. The standard/high/very-high sensitivity pairs `(minActivity, activityRatio)` are `(3.5, 0.125)`, `(3, 0.1)` and `(2.5, 0.08)`. New and older settings without this field default to standard. The disabled option stops detection and chain renewal; existing active stations expire through their normal timers. Setting changes apply on the next frame. Tests cover all three threshold boundaries, disabled detection, live switching and settings restoration; existing synthetic replays retain their original `(3.5, 0.125)` thresholds, now standard sensitivity. A seven-station synthetic replay verifies initial activation, expiry during quiet data, rejection of weak fluctuations borrowing old triggers, and successful activation on a fresh qualifying rise. P-Alert penalty eligibility is maintained independently of the rolling level history, as described below. The former background PGA ratio no longer contributes to activity; the PGA background comparisons are used only to start a new pick. The frozen function in `fixtures/palert_activity_before.mjs` verifies that the former ratio-based activity boost is removed. Tests also check frame-driven scheduling with actual Vue watchers, directional neighbors within 100 km, CWA matching/visibility, label fields and the shared Taiwan grid visibility rule. The 125-frame synthetic Taiwan replay uses the actual station class, level conversion, travel tables and solver, then checks event cleanup. It is a software regression scenario, not validation against a measured earthquake.

P-Alert penalty candidates track `nonQuietBoundaryStamp`, `missingCountSinceBoundary` and `consecutiveMissingCount`. Initialize the boundary one second before the first received frame. A valid level above 5 moves it to that frame and resets both counts. A valid level at or below 5 resets only the consecutive count. Missing frames increment both counts; more than 5% missing since the boundary, or at least three consecutive missing frames, moves the boundary to the current frame and clears only the cumulative count. Every further consecutive missing frame advances the boundary again. Base eligibility requires at least ten elapsed seconds, at most 5% missing and fewer than three consecutive missing frames; the current frame may be missing if these conditions hold. Gaps are counted from actual timestamps, independently of the sixty-frame history cap, with a constant-time shortcut for long gaps. Timeline/history resets clear all three fields. Each cluster further requires the boundary to be strictly earlier than its earliest owned trigger, using the original full pick set across all scenarios and duplicate refits. Old picks in other clusters no longer globally exclude P-Alert stations; NIED retains its original exclusion. The reference-distance selection and distance-based counting retain their existing rules; the shared weight now includes the breadth station bonus described above. Tests cover initialization, inclusive thresholds, gap recovery, coalesced snapshots, cluster merges, candidate-cache invalidation and shared scenario/refit evidence.

Every P-Alert station computes its trigger during each data update, before activation and independently of the inference setting. Already-active stations may renew directly only when the current frame's level is at least 10 and the trigger is valid. The twelve-second activity peak and display hold level do not qualify a station for direct renewal. Neighborhood scoring includes only positive-activity stations with valid triggers within `distance / 3.5 + 2` seconds of the center station, while the selected sensitivity threshold uses the complete detection-neighborhood count, including any 30-40 km supplements. Chains apply the same compatibility check to each adjacent pair. Distance tolerances are precomputed for activation neighbors when station metadata changes. Stations that receive no renewal keep the existing 12.5-second expiry timer; inactive stations still require neighborhood detection. Tests exercise same-frame activation with inference disabled, invalid triggers, tolerance boundaries, chain barriers and the full detection-neighborhood denominator. Adjacency tests cover self-inclusive counts, all local stations, nearest-first supplementation, exact 30/40 km boundaries, insufficient coverage, independent rows and activation through supplemental edges.

P-Alert sound, notification and focus triggers use active stations' maximum valid level in the latest sixty seconds, stored separately as `recentMaxLevel`. Display still uses the configurable `holdLevel`. History resets also clear the alert peak. Existing rising-edge and notification-reset behavior is retained, including another alert when an earlier peak has expired and a later peak rises again.

P-Alert maintains one current pick per station. With no current pick, t must be valid and t-1 through t-8 must be consecutive valid samples. The selected onset must have strictly positive PGA; zero PGA remains valid as background and as a later sample in an existing pick. First try backdating to t-1: at least one of t and t-1 must reach level 6, and PGA(t) and PGA(t-1) must each be at least 1.5 times the maximum PGA of t-2 through t-8. PGA(t-1) must also be greater than zero; a zero preceding sample rejects backdating and leaves the direct branch available. Either sample may be below level 6 provided the other reaches it; rising, equal and falling consecutive PGAs are allowed, and both samples initialize the pick's level/PGA statistics. This branch has priority even when direct pickup also qualifies. The preceding sample may be the previous pick's closing sample, so consecutive picks can share one boundary sample while retaining separate identities and independently accumulated metrics. If backdating is unavailable, direct pickup at t requires t itself to reach level 6 and PGA(t) to be at least twice the maximum PGA of t-1 through t-8. Background levels may be 6 or higher; there is no retrospective search beyond t-1 or extra rising-edge gate. During a pick, its trigger timestamp stays fixed; the top two levels and top two PGAs accumulate over the same valid sample interval, independently of the sixty-second history window. Different timestamps may contribute equal values. A numerical change to either of the top two PGAs resets the unchanged count, including the first valid observation that fills the second PGA. Equal values that leave both PGA statistics unchanged, and missing time points, increment the count. The eighth unchanged time point closes the pick immediately, even if activity remains positive. The closing sample contributes its level before the final snapshot is saved. New samples cannot update the closed pick; a later qualifying sample starts a separate pick with fresh metrics. Activity continues to use its independent twelve-second level maximum and does not itself close a pick. Missing seconds are processed before a returning sample, including gaps longer than the retained history. Duplicate or out-of-order frames cannot advance counters or contribute another peak. A completed-pick snapshot is offered alongside the latest active-station state on its closing frame, so pending updates preserve final metrics without restoring the cleared trigger. Only active stations submit current or completed picks. History/timeline resets clear current trigger state and unsent completed snapshots; ordinary pick closure preserves history, reminder peaks and the existing isActive timer. Tests cover both onset branches, their priority and inclusive boundaries, positive onsets over zero backgrounds, falling-pair confirmation and independent background thresholds, shared boundary samples with frozen old-pick metrics, separate pick identities, direct fallback, renewal at the seventh/eighth-count boundary, higher second PGAs, equal plateaus, long-running rises, short/long gaps, final-frame PGV-driven level changes, cumulative message merging, independent later picks and zero activity during a still-updating second PGA. Pick base weight is zero below level 6; levels 6 through 13 use 0.1, 0.4, 1.6, 2.4, 2.8, 3.2, 3.6 and 4, respectively, with higher levels capped at 4.

Its P/S count penalty uses threshold/cap pairs `(8, 1)` by default and `(9, 0.5)`, `(10, 0)`, `(11, 0)` for PREV filter levels 1, 2, 3. Zero caps disable only the phase-count penalty for those filter stages.

# Hypocenter checks

Run from the repository root with Node.js 20 or later:

```sh
node --experimental-vm-modules etc/hypocenter/test/compare_nied_profile.mjs
node --experimental-vm-modules etc/hypocenter/test/palert_inference.mjs
pnpm build
```

The P-Alert suite also exercises station-list polling in both P-Alert and TREM. Each starts immediately, retries twenty seconds (P-Alert) or ten seconds (TREM) after a request completes while no usable station metadata is cached, and refreshes every ten minutes once a valid list is available. Tests cover malformed and partial responses, preservation of cached metadata after refresh failures, and unmount during a pending request or scheduled delay.

NIED, P-Alert and TREM share `StationFrameQueue`, with an independent instance for each source. The `displaySeisNet.httpDataPriority` setting defaults to `realtime`, which commits successful responses immediately. In `complete` mode, one distinct later frame may wait behind unfinished requests; two distinct ready timestamps displace a blocking unfinished frame. Duplicate timestamps do not consume additional waiting allowance. NIED groups its 500ms attempts by the requested second, so any successful attempt satisfies that frame and failures wait only while another attempt is pending. Timestamp-specific replay requests also group by their requested second. P-Alert frames become ready after optional PGV retrieval; a PGV failure retains valid PGA. Failed, malformed and discarded requests cannot block indefinitely or reappear on late completion. Timeline resets discard pending work and allow an earlier timestamp; mode/source changes discard pending work while preserving committed time and station history. Tests exercise all three actual request callbacks with deferred responses, all three-frame return permutations, duplicate attempts, the one-frame limit, failure/timeout release, PGA/PGV readiness and lifecycle isolation. The queue preserves available frames; it cannot recover server-side gaps or missing station measurements.

The suite also checks NIED and P-Alert inference lifecycle handling. NIED validates both the Worker instance and request ID, ignores errors from replaced Workers, and clears displayed inference on a current Worker error. Initialization and reset discard pending work and the existing finder; reset retains adjacency. Virtual task-queue tests cover stale callbacks across generations. Both renderers keep inferred waves, epicenters and labels in a Leaflet layer group, remove the old group and label listeners when the map changes, and destroy them on unmount. Renderer checks cover result replacement, map replacement, disabled display, label modes, pane ownership and cleanup while retaining the source-specific time zone and label styling.

`compare_nied_profile.mjs` compares the current NIED finder with the original implementation at commit `2a420f4c5fe435688a6862147e0967e9393623fc`, including its original S/P thresholds without modifying the baseline. Sequential comparisons supply the original density-weight table to the current finder to isolate solver equivalence from the intentional density-policy change. It checks parameters, sequential results, internal state, PREV behavior and profile isolation.

NIED and P-Alert density weights both use `1 / sqrt(max(N, 1))`, where N counts initialized station neighbors at distances up to and including 30 km, including the station itself. Current data validity and activation do not affect this count, and distant neighbors added for directional connectivity are excluded. Each Worker computes the density table when it receives station initialization, reuses it across frame updates and finder resets, and replaces it on a new initialization. Direct finder construction without a supplied table computes the same policy once. The P-Alert suite verifies both source classes, the exact radius boundary, remote-link independence and Worker table reuse/reinitialization.

P-Alert inference retains all neighbors within 30 km, then fills each north/east/south/west direction to at least three neighbors by increasing distance, stopping at the inclusive 100 km boundary. The center station is retained but does not count toward any direction. A direction remains below three if too few stations exist within range; local directions already containing three or more receive no distant supplements. Activation neighborhoods and density weights still use the original 30 km radius. NIED uses the same supplementation rule with a minimum of two neighbors per direction and an inclusive 300 km limit, retaining its existing activation neighborhood. Tests cover nearest-first selection, preservation of all local neighbors, sparse/missing directions, the exact distance limits and density independence for both sources.

`palert_inference.mjs` covers trigger/missing-data boundaries, including the direct two-times PGA boundary, preferred one-frame backdating with a seven-point 1.5-times background, pick intervals sharing a boundary sample, complete preceding sample validation, cumulative top-two PGA renewal, closure after eight unchanged time points independently of activity, final-frame peak delivery, frozen completed picks, prevention of stale-trigger recovery, high-background onset validation, history-window independence, per-timestamp peak statistics, level-only activity, weighting, inactive penalties, cumulative message merging, Worker reuse/cancellation and settings access. Activity uses the maximum level in the latest twelve seconds: below 7 gives 0, levels 7/8/9 give 0.5/1/1.5, and level 10 or higher gives 2. The station's `activitySeconds` parameter controls this detection window independently of the pick lifecycle. Detection requires an activity sum of at least `max(neighborCount * 0.125, 3.5)`. A seven-station synthetic replay verifies initial activation, expiry during quiet data, rejection of weak fluctuations borrowing old triggers, and successful activation on a fresh qualifying rise. P-Alert penalty eligibility is maintained independently of the rolling level history, as described below. The former background PGA ratio no longer contributes to activity; the PGA background comparisons are used only to start a new pick. The frozen function in `fixtures/palert_activity_before.mjs` verifies that the former ratio-based activity boost is removed. Tests also check frame-driven scheduling with actual Vue watchers, directional neighbors within 100 km, CWA matching/visibility, label fields and the shared Taiwan grid visibility rule. The 125-frame synthetic Taiwan replay uses the actual station class, level conversion, travel tables and solver, then checks event cleanup. It is a software regression scenario, not validation against a measured earthquake.

P-Alert penalty candidates track `nonQuietBoundaryStamp`, `missingCountSinceBoundary` and `consecutiveMissingCount`. Initialize the boundary one second before the first received frame. A valid level above 5 moves it to that frame and resets both counts. A valid level at or below 5 resets only the consecutive count. Missing frames increment both counts; more than 5% missing since the boundary, or at least three consecutive missing frames, moves the boundary to the current frame and clears only the cumulative count. Every further consecutive missing frame advances the boundary again. Base eligibility requires at least ten elapsed seconds, at most 5% missing and fewer than three consecutive missing frames; the current frame may be missing if these conditions hold. Gaps are counted from actual timestamps, independently of the sixty-frame history cap, with a constant-time shortcut for long gaps. Timeline/history resets clear all three fields. Each cluster further requires the boundary to be strictly earlier than its earliest owned trigger, using the original full pick set across all scenarios and duplicate refits. Old picks in other clusters no longer globally exclude P-Alert stations; NIED retains its original exclusion. The reference-distance selection, distance-based counting and penalty weights are unchanged. Tests cover initialization, inclusive thresholds, gap recovery, coalesced snapshots, cluster merges, candidate-cache invalidation and shared scenario/refit evidence.

Every P-Alert station computes its trigger during each data update, before activation and independently of the inference setting. Already-active stations may renew directly only when the current frame's level is at least 10 and the trigger is valid. The twelve-second activity peak and display hold level do not qualify a station for direct renewal. Neighborhood scoring includes only positive-activity stations with valid triggers within `distance / 3.5 + 2` seconds of the center station, while the threshold is `max(neighborCount * 0.125, 3.5)` using the original neighborhood count. Chains apply the same compatibility check to each adjacent pair. Distance tolerances are precomputed for activation neighbors when station metadata changes. Stations that receive no renewal keep the existing 12.5-second expiry timer; inactive stations still require neighborhood detection. Tests exercise same-frame activation with inference disabled, invalid triggers, tolerance boundaries, chain barriers and the unchanged threshold denominator.

P-Alert sound, notification and focus triggers use active stations' maximum valid level in the latest sixty seconds, stored separately as `recentMaxLevel`. Display still uses the configurable `holdLevel`. History resets also clear the alert peak. Existing rising-edge and notification-reset behavior is retained, including another alert when an earlier peak has expired and a later peak rises again.

P-Alert maintains one current pick per station. With no current pick, t must be valid and t-1 through t-8 must be consecutive valid samples. The selected onset must have strictly positive PGA; zero PGA remains valid as background and as a later sample in an existing pick. First try backdating to t-1: at least one of t and t-1 must reach level 7, and PGA(t) and PGA(t-1) must each be at least 1.5 times the maximum PGA of t-2 through t-8. PGA(t-1) must also be greater than zero; a zero preceding sample rejects backdating and leaves the direct branch available. Either sample may be below level 7 provided the other reaches it; rising, equal and falling consecutive PGAs are allowed, and both samples initialize the pick's level/PGA statistics. This branch has priority even when direct pickup also qualifies. The preceding sample may be the previous pick's closing sample, so consecutive picks can share one boundary sample while retaining separate identities and independently accumulated metrics. If backdating is unavailable, direct pickup at t requires t itself to reach level 7 and PGA(t) to be at least twice the maximum PGA of t-1 through t-8. Background levels may be 7 or higher; there is no retrospective search beyond t-1 or extra rising-edge gate. During a pick, its trigger timestamp stays fixed; the top two levels and top two PGAs accumulate over the same valid sample interval, independently of the sixty-second history window. Different timestamps may contribute equal values. A numerical change to either of the top two PGAs resets the unchanged count, including the first valid observation that fills the second PGA. Equal values that leave both PGA statistics unchanged, and missing time points, increment the count. The eighth unchanged time point closes the pick immediately, even if activity remains positive. The closing sample contributes its level before the final snapshot is saved. New samples cannot update the closed pick; a later qualifying sample starts a separate pick with fresh metrics. Activity continues to use its independent twelve-second level maximum and does not itself close a pick. Missing seconds are processed before a returning sample, including gaps longer than the retained history. Duplicate or out-of-order frames cannot advance counters or contribute another peak. A completed-pick snapshot is offered alongside the latest active-station state on its closing frame, so pending updates preserve final metrics without restoring the cleared trigger. Only active stations submit current or completed picks. History/timeline resets clear current trigger state and unsent completed snapshots; ordinary pick closure preserves history, reminder peaks and the existing isActive timer. Tests cover both onset branches, their priority and inclusive boundaries, positive onsets over zero backgrounds, falling-pair confirmation and independent background thresholds, shared boundary samples with frozen old-pick metrics, separate pick identities, direct fallback, renewal at the seventh/eighth-count boundary, higher second PGAs, equal plateaus, long-running rises, short/long gaps, final-frame PGV-driven level changes, cumulative message merging, independent later picks and zero activity during a still-updating second PGA. Pick base weight is zero below level 7; levels 7 through 13 use 0.2, 0.8, 1.2, 1.4, 1.6, 1.8 and 2, respectively, with higher levels capped at 2.

For a browser check, start `pnpm dev --host 127.0.0.1 --port 5174` and open `/etc/hypocenter/test/palert_browser.html`. Run the synthetic event, switch between basic/detailed labels, toggle the matching CWA event and the always-on override, clear the result, and unmount the component. Enable/display changes take effect on the next frame/result, as in NIED. Restart the synthetic event after its picks have expired. This mounts the actual `PalertNet.vue` with an isolated in-memory settings store and synthetic station data, exercising its Worker scheduling, Leaflet wave circles, UTC+8 labels and cleanup without contacting a station API or persisting settings.

P-Alert initially copies the existing search parameters and uses JMA2001/JB travel tables. Its P/S count penalty uses threshold/cap pairs `(8, 2)` by default and `(9, 1.5)`, `(10, 1)`, `(11, 0.5)` for PREV filter levels 1, 2, 3. Each unit of S/P ratio above the threshold adds 0.5 penalty, up to the cap. NIED uses `(3, 2)`, `(3.5, 1.5)`, `(4, 1)`, `(4.5, 0.5)` in the same order and retains its slope of 1. Tests cover threshold boundaries, fractional ratios, caps, pure P, pure S and S-heavy inputs, plus origin-time and arrival-time checks in the synthetic Taiwan replay. Real-event replay is still needed to calibrate Taiwan travel-time accuracy, threshold-crossing delay, residual gates and quality ranks. P-Alert settings are isolated in `src/classes/PalertHypocenterProfile.js`; tuning them must retain the NIED comparison checks.
